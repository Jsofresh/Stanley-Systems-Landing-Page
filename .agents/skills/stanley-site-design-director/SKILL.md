# Stanley Systems Site Design Director

Use this skill whenever the task touches the Stanley Systems public website, homepage sections, landing pages, CTAs, calculator flow, visual design, page copy, or responsive polish.

## Role

Act as product lead, UX lead, design director, and frontend implementer. Your job is not just to make code compile. Your job is to make the public site feel premium, practical, money-first, and credible for service-business owners.

## Required context before editing

Before changing website UI or copy:

1. Read `DESIGN.md` in the repo root.
2. Read the relevant component/page files.
3. If the task involves homepage redesign, read any active redesign brief or plan file referenced by the user or repo notes.
4. Identify locked copy and protected scope before editing.

## Core public positioning

Stanley Systems fixes office-side gaps that slow billing, break follow-up, and force the owner to become the backup system.

Lead with:
- more collected revenue
- faster cash movement
- fewer delayed invoices
- fewer missed calls
- more repeat customers
- fewer payroll hours wasted on office cleanup
- less owner rescue work

Do not lead with:
- AI
- automation
- integrations
- workflow optimization
- digital transformation
- technical plumbing

## Public naming rules

Use `Stanley Systems` in public-facing website copy when referring to the business.

Public first step:
- `Workflow Audit`

Public offer/package names:
- `Cashflow Control System`
- `Customer Revenue System`

Do not invent new offer names unless the user explicitly asks.

## Visual direction

Use a premium light-mode service-business design language:

- warm off-white canvas
- navy text
- Stanley green accent
- white cards only where useful
- thin warm-neutral borders
- soft shadows
- generous spacing
- oversized confident headlines
- tight premium typography
- minimal chrome
- subtle visual depth
- smooth native motion

Useful references by principle, not by literal copying:
- Apple: cinematic whitespace, restraint, scale.
- Wise: direct money-first clarity and green confidence.
- Stripe/Webflow/Framer: section rhythm, polished surfaces, crisp responsive layout.
- Notion/Cal.com: restraint and clean neutral utility.

## Hard visual bans

Do not add:
- black or dark sections
- orange, amber, loud purple, rainbow, neon, or random gradients
- generic SaaS icon grids
- fake dashboards unless the brief explicitly asks for a dashboard
- random KPI boxes
- random cards just to fill space
- YouTube, GIFs, embeds, or external media players
- cluttered glassmorphism
- wonky offsets
- bounce animations

## Copy rules

Write plain English for service-business owners. A plumber, HVAC owner, or marine shop owner should instantly understand what changes in their day.

Prefer:
- get paid faster
- stop losing good leads
- turn finished work into collected cash
- bring back customers you already earned
- free the owner from office cleanup
- catch missed calls
- follow up before money leaks out

Avoid:
- optimize
- streamline
- transform
- empower
- innovative
- cutting-edge
- synergy
- ecosystem
- leverage
- scalable solution
- AI-powered

Do not use em dashes or en dashes in public-facing website copy. Use periods, commas, colons, or parentheses.

## Section workflow

When asked to redesign a section:

1. Modify only that section and necessary shared chrome.
2. Do not redesign downstream sections unless explicitly asked.
3. Preserve locked copy exactly.
4. Keep the conversion path consistent with the brief.
5. Verify desktop and mobile.
6. Run the local build if code changed.
7. Report changed files, verification, divergences, and risks.

## Responsive requirements

Always check mobile. Mobile cannot be an afterthought.

Watch for:
- clipped CTAs
- prompt or CTA falling below the viewport
- sticky CTA appearing where the brief says no CTA
- nav wrapping or overlapping
- overlarge headings that crush the section
- background art interfering with text

## Motion rules

Motion should feel premium and disciplined:
- fade/up
- subtle parallax only if useful
- smooth transitions
- no bounce
- no theatrical loops
- respect `prefers-reduced-motion`

## Quality bar

If the design looks like a generic SaaS landing page, it is wrong.

A good Stanley Systems page should feel:
- clear
- financially grounded
- professional
- practical
- premium
- service-business fluent
- conversion-focused without looking desperate
